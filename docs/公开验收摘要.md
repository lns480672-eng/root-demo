# ROOT 公开验收摘要

工作台使用生成 Agent 把需求变成可操作的工具。发布前分别检查生成结果能否在隔离环境里运行、账号能否找回数据，以及修改失败时旧工具能否继续使用。需求编号和交接步骤见[实施计划](实施计划.md)与[开发与验收流程](开发与验收流程.md)。

## 反馈 11 和 18：重复提交与连接恢复

修改运行时仍可再次提交，连接中断后用户也难以判断上一次提交是否已受理。修复后，服务端用请求标识识别重试，拦住同一账号同时发起的另一个任务。工作台在连接恢复后核对原任务。

| 层级 | 本地验收观察 |
| --- | --- |
| 界面 | 在 Chrome 模拟服务已受理但响应丢失，以及读取任务时断连。用户重试后回到原任务，旧工具仍可录入，刷新后能读回。 |
| API | 同账号的两次并发提交一次受理、一次返回 HTTP 409。重试沿用同一请求标识，模型只派发一次，另一账号可独立提交。 |
| 数据 | 复查任务、工具、记录和额度，确认重试没有重复创建工具或重复计次。已有记录发生并发写入时，旧确认失效，重新确认后同一工具只升一版。 |

独立 QA 和产品验收均通过，范围为 AC-007、AC-018-B2、AC-018-C，固定构建为 `v4-375d927da357`。测试使用隔离数据库和模型替身。历史公网断连的原始日志不足，根因仍待确认。

## 反馈 17：生成网站的样式是否实际生效

生成页面曾出现样式未生效的问题。校验在浏览器渲染后读取样式效果，拦截空样式和无效样式，并把失败原因交给生成 Agent。候选未通过检查时，保存门禁会阻止该候选生效。

独立 QA 和产品针对 AC-001 通过本地验收，固定构建为 `v4-2c890d31d06a`。真实模型用咖啡和单车两组需求生成网站，在桌面和窄屏检查样式和页面切换，并刷新确认能重开同一工具。

## 从公开仓库复跑

在仓库根目录运行。测试使用自带模型替身，浏览器相关检查需要 Node.js 和支持出站限制的 Chrome 或 Chromium，环境配置见[启动说明](../README.md#本机启动)。

```sh
PYTHONPATH=tests python3 -B -m unittest \
  test_staged_http.StagedReconnectHTTP.test_reconnect_replays_one_generation_and_publication_after_server_restart \
  test_staged_http.StagedHTTP.test_revision_answer_reuses_task_and_deduplicates_dispatch \
  test_staged_http.StagedHTTP.test_revision_runtime_check_rejects_concurrent_data_write
PYTHONPATH=tests python3 -B -m unittest discover -s tests -p 'test_runtime_verify.py'
```

这些命令复跑当前源码的自动化回归。上面的历史验收按各自构建记录，原始日志和发布环境配置由项目本地保管。更多覆盖范围见[测试证据索引](测试证据索引.md)。
